# Системи опалення — розрахунок і підбір

Настільна програма (Windows, WPF, .NET 8) для інженерного розрахунку теплового навантаження будинку,
річної потреби в енергії та підбору системи опалення. Порівнює котли, централізоване опалення й теплові
насоси за експлуатаційними витратами та викидами CO₂. Підбирає конкретні моделі теплових насосів
із каталогу **9 075 сертифікованих моделей від 174 виробників**.

> Оригінальну версію проєкту (до переробки) збережено в гілці `backup/original-project`.

## Можливості

| Сторінка | Що робить |
|---|---|
| **Будівля** | Введення кліматичних, геометричних і теплотехнічних даних. Коефіцієнти U конструкцій розраховуються «наживо», а помилки введення підсвічуються. |
| **Результати** | Розрахункове теплове навантаження, структура тепловтрат, річна потреба, розподіл потреби за зовнішньою температурою, перевірка за ДБН В.2.6-31. |
| **Порівняння** | Річні витрати (грн), паливо й CO₂ для 8 типів генераторів теплоти та найкращих теплових насосів. |
| **Підбір ТН** | Сезонне моделювання кожної придатної моделі для вашої будівлі. Можна обмежити джерело теплоти, холодоагент, шум і завищення потужності. |
| **Каталог** | Пошук і фільтрація всіх моделей; для кожної — робочі точки COP і відтворений моделлю SCOP. |
| **Довідники** | Тарифи (можна редагувати), клімат, матеріали, вікна, генератори теплоти, джерела даних. |
| **Проєкти** | Збереження та відкриття розрахунків (SQLite). |

Звіт про розрахунок експортується в HTML (Ctrl+P); його можна роздрукувати або зберегти в PDF із браузера.

## Методика

| Величина | Формула / стандарт |
|---|---|
| Коефіцієнт теплопередачі | U = 1 / (R_si + Σ d/λ + R_se), EN ISO 6946 (R_se = R_si для неопалюваних просторів) |
| Підлога по ґрунту | EN ISO 13370: B′ = A/(0,5P), d_t = w + λ_g(R_si + R_f + R_se); періодичний коефіцієнт H_pe = 0,37·P·λ·ln(δ/d_t + 1) |
| Теплове навантаження | EN 12831: Φ = Σ A·(U + ΔU_TB)·b·(θi − θe) + f_g1·f_g2·A·U_g·(θi − θe) + 0,34·V̇·(θi − θe) |
| Інфільтрація / вентиляція | V̇_inf = V·n50·e; природна V̇ = max(V̇_inf, n·V); механічна V̇ = V̇_inf + n·V·(1 − η_рек) |
| Річна потреба | bin-метод: години опалювального періоду розподілено за температурою (нормальний розподіл, середнє = θср.оп, θe ≈ квантиль 3,3σ); у кожному інтервалі враховано теплонадходження з коефіцієнтом використання EN ISO 13790: η = (1 − γ^a)/(1 − γ^(a+1)) |
| Опалювальний графік | θ_под = θi + (θ_под,р − θi)·x^(1/n), x = (θi − θ)/(θi − θe), n = 1,3 (радіатори) / 1,1 (тепла підлога) |
| Тепловий насос | модель hplib: COP = p1·T_in + p2·T_out + p3 + p4·T_amb; інвертор: P_el,max = P_el,ref, P_el,min = 25 %; циклування EN 14825: COP·CR/(0,9·CR + 0,1); нижче TOL і при нестачі потужності працює ТЕН |
| Гаряча вода | Q = N·V·365·1,163·10⁻³·(θг − θх)·(1 + f_втрат) |
| Котли | сезонний ККД за нижчою теплотою згоряння; для конденсаційних котлів ККД зростає зі зниженням температури подачі |

**Перевірка моделі теплового насоса.** Автоматичний тест відтворює сертифікований SCOP кожної з 9 075 моделей
bin-методом EN 14825 («середній» клімат, 35 °C) за коефіцієнтами регресії. Медіанна похибка — ≈ 4 %,
у 90 % моделей — менше 8 %.

## Дані

* **Каталог теплових насосів** — результати сертифікації [Heat Pump KEYMARK](https://keymark.eu), оброблені проєктом
  [hplib](https://github.com/FZJ-IEK3-VSA/hplib) (Forschungszentrum Jülich, ліцензія MIT, коміт `125c2ef`).
  Вихідний файл: `database/raw/hplib_database.csv`. Під час імпорту відкинуто 14 узагальнених («Generic») записів,
  856 повних дублікатів і 8 записів із нефізичною моделлю COP. Усі позиції каталогу — реальні сертифіковані продукти;
  жодну не вигадано.
* **Клімат** — довідкові значення для обласних центрів за ДСТУ-Н Б В.1.1-27:2010. Цей документ не вдалося
  завантажити під час підготовки, тому перед використанням у проєктній документації значення **потрібно звірити**
  з таблицями стандарту. Усі значення можна змінити в базі даних.
* **Тарифи та коефіцієнти CO₂** — орієнтовні (2024–2025 рр.), редагуються на сторінці «Довідники».
* **Матеріали та вікна** — ДСТУ Б В.2.6-189:2013, EN ISO 10456, EN ISO 10077-1 (типові значення).
* **Вимоги до огороджувальних конструкцій** — ДБН В.2.6-31:2016, табл. 3.

## База даних

SQLite-файл `database/heating_catalog.db` поставляється разом із програмою. Під час першого запуску його копіюють
до `%LOCALAPPDATA%\HeatingSystems\heating.db` — там зберігаються проєкти та змінені тарифи. Коли виходить новий
каталог, програма переносить проєкти й тарифи користувача автоматично (а стару копію зберігає як `.bak`).

```
database/
  schema.sql            схема (довідники, каталог, проєкти, представлення v_heat_pumps, індекси)
  seed_reference.sql    довідкові дані з джерелами для кожного значення
  raw/                  вихідні дані hplib + ліцензія
  heating_catalog.db    зібрана база (генерується)
tools/
  build_catalog.py      збірка бази (лише стандартна бібліотека Python)
  verify_catalog.py     перевірка, що закомічена база відтворюється з вихідних даних
```

Перезбирання бази: `python tools/build_catalog.py`

## Структура рішення


## Збирання та запуск

Потрібні Windows 10/11 і [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) (або Visual Studio 2022 17.8+).

```
dotnet build HeatingSystems.sln -c Release
dotnet test  HeatingSystems.sln -c Release
dotnet run   --project src/HeatingSystems.App
```

Ядро й тести бази збираються та запускаються й на Linux/macOS:
`dotnet test tests/HeatingSystems.Tests`.

### Запуск без встановлення .NET

1. Відкрийте вкладку **Actions** репозиторію → останній успішний запуск **CI** → розділ **Artifacts**.
2. Завантажте `HeatingSystems-win-x64` (потрібен вхід у GitHub) і розпакуйте архів у будь-яку папку.
3. Запустіть `HeatingSystems.exe`. Якщо з'явиться попередження Windows SmartScreen, натисніть
   «Докладніше» → «Виконати в будь-якому разі» (програма не підписана цифровим підписом).

Збірка самодостатня (.NET 8 уже всередині) і працює на Windows 10/11 x64. Файл `heating_catalog.db` має лежати поруч
з `.exe`. Проєкти користувача зберігаються в `%LOCALAPPDATA%\HeatingSystems\heating.db`.

Гарячі клавіші: **F5** — розрахувати, **Ctrl+S** — зберегти, **Ctrl+N** — новий проєкт, **Ctrl+P** — звіт.

## Обмеження

* Будівля розглядається як одна теплова зона. Сонячні теплонадходження не враховуються, тож результат
  потреби виходить із запасом.
* Розподіл годин зовнішньої температури апроксимовано за кліматичними параметрами. Для точніших розрахунків
  потрібні погодинні кліматичні дані (наприклад, файли TMY).
* Рейтинг теплових насосів враховує лише експлуатаційні витрати. Вартість обладнання, монтажу та буріння
  свердловин у каталозі відсутня.
